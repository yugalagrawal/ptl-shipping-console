03 Live pricing preview

Create Order doesn't run its own freight math — it calls the exact same computeOrderPricing() that Network Simulator's Freight Calculator uses, seeded from the client's real tier and zone-to-zone matrix. If you're adding a new charge type or changing how a zone is classified, change it once in data/pricing.js and both screens update together.

Numeric input conventionPackage weight/count fields clamp to non-negative on change (clampNonNegative()) rather than allowing a stray minus sign through to the pricing engine — reuse this helper for any new numeric field that shouldn't go below zero.

05 If you're building here

  • Booking a new kind of shipment? Extend ORDERS_SEED's shape in data/orders.js rather than adding a parallel array — every downstream module (Trip, Invoicing, MIS, Warehouse) reads from this one source.
  • New freight charge? Add it to the additional-charges master in data/pricing.js (Client Module reference) so it's available to both Create Order and Freight Calculator automatically.
  • An order's onward journey — lane grouping, manifest, truck, delivery — lives in Trip Module and Supply & Fleet Module, not here.
