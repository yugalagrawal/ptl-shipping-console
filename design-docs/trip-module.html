Trip Module

Order aggregation, multi-leg trip construction, and execution tracking — where individual orders stop being individual and become a manifest riding one truck down one lane.

Sidebar group: Trip Module Base route: /trip-management/* Files: src/pages/trip/*.jsx Design tokens: see Design System

The routing/matching logic here is deliberately the concrete, buildable slice of trip planning — lane-based grouping, not full multi-leg (FM/MM/LM) construction or AI route prediction, which are still open scope.

02 Screens

Routing Simulator/trip-management/routing-simulator

Orders past "Inward at Origin Hub" get grouped by lane (eligibleOrdersByLane()). Each order in a group is checked by default and can be deselected before building; confirming a group calls buildManifest(), which is what actually lands the manifest in Supply & Fleet's Truck Assignment queue.

04 If you're building here

  • Building real multi-leg (FM/MM/LM) trip construction? Routing Simulator's lane-grouping is the intentional starting point — extend buildManifest(), don't bypass it.
  • A trip's truck comes from Supply & Fleet Module — Truck Assignment is what actually calls createTripFromAssignment(), not this module.
  • New trip status? Add it to TRIP_STATUS_LABEL/TRIP_STATUS_BADGE in data/trips.js, then decide whether Tracking's "active" filter should include it.
