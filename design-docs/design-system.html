The PTL Console design system

Every color, type size, and component pattern already live in the shipped app — this page pulls them out of tailwind.config.js, src/components/ui.js, and the wizard/table code so the team builds new modules with the same hand, not five different hands.

Source of truth: live code, not guesses Core token file: src/components/ui.js Base font: Inter (Google Fonts) → system-sans fallback Read next: your module's own reference file

08 Form controls

Two intentional scales, not one accidental one: a roomier scale for data-entry forms (onboarding wizards), a denser scale for filter bars on list pages. Name both when you use them.

Form scale — Field, SelectField, Toggle

rounded-xl bg-slate-50/60 px-3.5 py-2.5
Field · same sizing as SelectField
Copy rates from existing client

Compact scale — filter bars & toolbars

rounded-lg px-3 py-1.5 · used in list-page toolbars, not data-entry forms
Don't mix mid-formBoth scales are legitimate — the inconsistency is only when the same screen uses rounded-lg in one field and rounded-xl in the next. Pick by context (form vs. toolbar), not file.

12 Standardization notes

Everything above is already true of the shipped app. These seven spots are where two conventions coexist by accident rather than by design — worth a five-minute team decision before the codebase grows to eight more modules and the drift compounds.

  • mixedRemove-link color
    text-rose-500 in four places, text-rose-600 in three, for the identical "remove this row" action. Pick rose-600 — it's already the one used for the one filled danger button.
  • mixedDisabled button treatment
    Primary CTAs disable by either recoloring to slate or dropping to 40% opacity, depending on the file. Recolor for filled buttons (keeps text legible), reserve opacity for outline/ghost buttons.
  • duplicateSmall "add a row" chip button
    Hand-typed identically six-plus times (rounded-lg border px-3 py-1.5 text-xs). Worth promoting to btnChip in ui.js alongside btnPrimary/btnSecondary so the next module imports it instead of retyping.
  • duplicateTIER_BADGE map
    Defined once in NewClient.jsx and once in data/pricing.js with identical values. Import from data/pricing.js going forward — one copy, one place to add a new tier.
  • mixedCard radius inside cards
    Nested panels sometimes reuse the full card (2xl + shadow) instead of the flatter xl variant, which visually doubles the "elevation" of a sub-section. Reserve shadow for the outermost card per screen.
  • mixedInput density
    Two legitimate scales (form vs. compact toolbar) sometimes mix within one screen's filter bar. Decide per-screen, not per-field.
  • mixedAgeing / POD status pills
    Collections.jsx and PastTrips.jsx build their status color with an inline ternary instead of a named map in data/, unlike every other status pill in the app. Fine for now, but the next person extending either screen should promote it to a data-file constant to match the rest.
