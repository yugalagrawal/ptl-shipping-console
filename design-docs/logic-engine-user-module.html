Logic Engine, User Module & System Info

Three smaller, meta-level areas grouped into one reference: the rules that steer every other module, who's allowed to touch what, and a read-only map of how it all connects.

01 Logic Engine

Route: /logic-engine File: src/pages/LogicEngine.jsx

Currently a landing page only — four labeled placeholder cards (Client Attributes, Supply-Demand, Route Planning, Prioritization), each tagged "Coming soon." The tagline on the page is the clearest scope statement in the app: "not a page you visit to move an LR, a page you visit to change how every LR moves."

If you're building one of these fourEach card's content lives in MODULES (data/modules.js) as a child of the logic-engine entry — give it a real to route and it'll automatically stop rendering as "Coming soon" and start behaving like a normal sidebar link.

02 User Module

Sidebar group: User Module Base route: /user-module/* Files: src/pages/admin/*.jsx
Access Management/user-module/access-management

Search an LT Team user, then edit their roles, function-level permissions and city/branch access. Roles imply a default function set (functionsForRoles()); editing functions individually marks the user as "custom" (isCustomDraft()) so it's visible when someone's access has drifted from their role's default.

role → function derivationcustom-drift detection
User Relations/user-module/user-relations

Maps reportees to managers. A manager can delegate from their own effective access down to a reportee — capped at the manager's own effectiveFunctions(), so nobody can delegate a permission they don't hold themselves. A plain manager reaches this page scoped to only their own reports even without the org-wide user-relations.manage permission.

delegation ceiling = manager's own accessmanager bypass for own reports

03 System Info

Route: /system-info File: src/pages/SystemInfo.jsx

A read-only reference page, not an operational screen — kept as its own flat sidebar entry rather than folded into a group, same treatment as Warehouse & Hub Ops. Explains how every module connects, which makes it a reasonable second read after this reference suite for anyone new to the codebase.

04 If you're building here

  • Adding a new permission-gated feature anywhere in the app? Register the function in data/permissions.js first — Access Management and User Relations both read from that single list, nothing is hardcoded per-module.
  • A new module's nav entry belongs in data/modules.js's MODULES array — the sidebar, permission checks, and Logic Engine's placeholder cards all derive from it automatically.
